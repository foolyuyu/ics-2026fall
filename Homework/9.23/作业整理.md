### 2.59

```c
#include <stdio.h>

int main(void) {
    unsigned x, y;
    scanf("%x %x", &x, &y);
    unsigned result = (x & 0xFFu) | (y & ~0xFFu); // 这里使用~0xFFu避免只适用于32位
    printf("0x%08X\n", result);

    return 0;
}
```

### 2.60

```c
#include <stdio.h>

unsigned replace_byte(unsigned x, int i, unsigned char b) {
    unsigned shift = (unsigned)i << 3;
    unsigned mask = ~(0xFFu << shift);
    unsigned result = ((unsigned)b << shift) | (x & mask);
    return result;
}

int main() {
    unsigned x;
    int i;
    unsigned char b;
    scanf("%x %d %hhx", &x, &i, &b);
    unsigned result = replace_byte(x, i, b);
    printf("0x%08X\n", result);

    return 0;
}
```

### 2.71

```c
#include <stdio.h>

typedef unsigned packed_t;
int xbyte(packed_t word, int bytenum);

/* 错误的代码
 * int xbyte(packed_t)
 * {
 *    return (word >> (bytenum << 3)) & 0xFF;
 * }
 *
 * 错误在：每一个字节都是有符号字节，如果取到的字节最高位为1，是负数，但是这种扩展方式只能扩出来正数
 */
int xbyte(packed_t word, int bytenum) {
    unsigned shift = (unsigned)bytenum << 3;
    int result = (int)((word >> shift) << 24) >> 24; //int类型左移把符号消掉是未定义行为，最好先用unsigned左移然后再转int赋予符号含义
    return result;
}

int main() {
    packed_t word;
    int bytenum;
    scanf("%x %d", &word, &bytenum);
    printf("%d\n", xbyte(word, bytenum));

    return 0;
}
```
注：错误原因已写在注释中了

### 2.89

已知 `int` 使用 32 位补码表示，`float` 使用 32 位 IEEE 格式，`double` 使用 64 位 IEEE 格式：

```c
int x = random();
int y = random();
int z = random();

double dx = (double)x;
double dy = (double)y;
double dz = (double)z;
```

判断下列表达式是否总是得到 `1`。若是，说明依据的数学原理；若不是，给出一个使表达式得到 `0` 的反例。

| 小题 | 表达式 | 总是得到 `1`？ | 数学原理或反例 |
| --- | --- | :---: | --- |
| A | `(float)x == (float)dx` | 是 | `double` 有 53 位有效精度，可以精确表示任意 32 位 `int`。因此直接将 `int` 转为 `float`，与先无损转为 `double`、再按相同规则舍入为 `float`，结果始终相同。 |
| B | `dx - dy == (double)(x - y)` | 否 | 虽然 `int` 转为 `double` 不会损失精度，但右侧的 `int - int` 可能先发生溢出；左侧在 `double` 中运算，可以精确表示两个 32 位整数之差。反例：`x = INT_MAX`（`0x7FFFFFFF`）、`y = INT_MIN`（位模式 `0x80000000`）。补码回绕时右侧的整数差为 `-1`，左侧则为 $2^{32}-1$，因此两者不相等。（严格按 C 标准，带符号整数溢出属于未定义行为。） |
| C | `(dx + dy) + dz == dx + (dy + dz)` | 是 | `dx`、`dy`、`dz` 都是由 32 位 `int` 精确转换得到的。三个数之和的绝对值小于 $3\times2^{31}<2^{33}$，中间结果和最终结果都能由具有 53 位有效精度的 `double` 精确表示，不会发生溢出或舍入，因此此处加法结合律成立。 |
| D | `(dx * dy) * dz == dx * (dy * dz)` | 否 | 浮点乘法的中间结果可能发生舍入，因此不满足结合律。反例：`x = 3`、`y = 4194305`（$2^{22}+1$）、`z = INT_MAX`。左侧结果为 $27021604194091004$，右侧结果为 $27021604194091008$，两者不相等。 |
| E | `dx / dx == dz / dz` | 否 | 反例：`x = 0`、`z = 1`。此时 `dx / dx` 为 $0.0/0.0=\mathrm{NaN}$，而 `dz / dz` 为 $1.0/1.0=1.0$；NaN 与任何值（包括自身）比较都不相等，因此表达式得到 `0`。 |

> 备注：数据都是自己在草稿纸上手算后填到表格里面的，草稿纸太乱，就不放上来了。
